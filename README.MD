# Cosmetic Inventory System - система учёта косметики

Учебное приложение на Python с веб-интерфейсом на Django для учёта косметических средств, контроля запасов и сроков годности.

## 1. Назначение проекта

Cosmetic Inventory System предназначена для хранения сведений о косметических средствах и работы с ними.

Приложение позволяет:

- просматривать список косметических средств;
- открывать подробную информацию о выбранном средстве;
- контролировать количество косметики;
- отслеживать сроки годности;
- определять средства, требующие пополнения или замены;
- искать средства по названию, бренду или категории;
- сортировать средства по сроку годности;
- изменять количество и удалять средства;
- просматривать сводную статистику;
- хранить данные между запусками приложения.

Проект развивается поэтапно: консольная версия приложения сохранена, а веб-интерфейс постепенно переводится на возможности Django.

## 3. Предметная область

Основная сущность системы - косметическое средство (`Product`). В реляционной
базе отдельно представлены средства, бренды и категории.

Объект `Product` содержит:

- `id` - уникальный идентификатор;
- `name` - название средства;
- `brand` - бренд;
- `category` - категория;
- `quantity` - количество единиц;
- `expiry_date` - срок годности.

Класс `Product` поддерживает проверку данных, изменение количества, определение состояния запасов и срока годности. Также реализованы операции поиска, сортировки, удаления и расчёта статистики.

Данные веб-приложения хранятся в отдельной базе SQLite. Доступ к ней выполняется
непосредственно через `sqlite3` и SQL, без Django ORM. JSON-файл сохранён как
исходный набор данных и используется скриптом импорта.

## 5. Веб-интерфейс

Веб-часть приложения реализована на Django.

Основные страницы:

- `/` - главная страница;
- `/products/` - список косметических средств;
- `/products/?q=<запрос>` - поиск по названию, бренду или категории;
- `/products/?category=<категория>` - фильтрация по категории;
- `/products/attention/` - средства с низким остатком или близким сроком годности;
- `/products/statistics/` - сводная статистика по категориям и брендам;
- `/products/<product_id>/` - подробная информация о средстве;
- `/products/<unknown_id>/` - страница отсутствующего средства с кодом 404;
- неизвестный адрес - общая страница ошибки 404 при `DEBUG = False`.

Для формирования страниц используются Django-шаблоны. Генерация HTML непосредственно в Python-коде веб-представлений не применяется, функция `page()` удалена.

View-функции выполняют запросы к SQLite, вычисляют необходимые статусы и
передают подготовленные значения в шаблоны через контекст. Результаты SQL
возвращаются как `sqlite3.Row`, поэтому поля доступны по именам.

В текущем веб-интерфейсе доступны список и карточка средства, поиск,
фильтрация, контроль средств, требующих внимания, и статистика. Создание,
редактирование и удаление средств через веб-формы пока не реализованы.

## 6. Django Template Language

Шаблоны используют возможности Django Template Language.

### Базовый шаблон

Общая HTML-структура страниц находится в:

```text
templates/base.html
```

Базовый шаблон подключает Bootstrap, собственные статические файлы, навигацию и содержит блоки для заголовка и основного содержимого:

```django
{% block title %}{% endblock %}
{% block content %}{% endblock %}
```

Дочерние шаблоны наследуют его:

```django
{% extends "base.html" %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные файлы:

- `templates/includes/navigation.html` - общая навигация;
- `templates/products/includes/product_card.html` - карточка средства в списке.

Они подключаются тегом `include`:

```django
{% include "includes/navigation.html" %}
{% include "products/includes/product_card.html" with product=item.product needs_attention=item.needs_attention only %}
```

### Контекст

Представления передают данные в шаблоны через словарь контекста. Например, страница списка получает заголовок и подготовленную коллекцию средств:

```python
context = {
    "page_title": "Косметические средства",
    "product_items": product_items,
}
```

В шаблонах значения доступны по именам переменных:

```django
{{ page_title }}
{{ product.name }}
```

### Циклы и условия

Список средств формируется циклом:

```django
{% for item in product_items %}
{% empty %}
{% endfor %}
```

Тег `empty` обеспечивает отдельное отображение пустой коллекции.

Условия используются для вывода статуса средства и активного пункта навигации:

```django
{% if needs_attention %}
    Требует внимания
{% else %}
    В порядке
{% endif %}
```

## 7. Фильтры шаблонов

В шаблонах применяются стандартные фильтры Django Template Language:

```django
{{ product_items|length }}
{{ product.brand|default:"Не указан" }}
{{ product.expiry_date|date:"d.m.Y" }}
```

Фильтры отвечают только за представление данных. Бизнес-логика определения остатков и сроков годности остаётся в Python-коде предметной области.

## 8. URL-маршрутизация

Для приложений заданы пространства имён:

Используются именованные маршруты:

- `homepage:index`;
- `products:list`;

Ссылки в шаблонах формируются тегом `url`, а не жёстко заданными адресами:

## 10. База данных и SQL

После выполнения ПР7 данные веб-приложения перенесены из
`data/products.json` в `data/cosmetic_inventory.sqlite`. JSON-хранилище
сохранено как предыдущая реализация и источник для повторного импорта.

Структура базы создаётся командами из `sql/schema.sql` и включает три таблицы:

- `brands`: `id INTEGER PRIMARY KEY`, `name TEXT NOT NULL UNIQUE`;
- `categories`: `id INTEGER PRIMARY KEY`, `name TEXT NOT NULL UNIQUE`;
- `products`: `id INTEGER PRIMARY KEY`, `name TEXT NOT NULL`,
  `brand_id INTEGER NOT NULL`, `category_id INTEGER NOT NULL`,
  `quantity INTEGER NOT NULL`, `expiry_date TEXT NOT NULL`.

Внешние ключи связывают `products.brand_id` с `brands.id`, а
`products.category_id` - с `categories.id`. Для количества действует проверка
`quantity >= 0`. Срок годности хранится в формате `YYYY-MM-DD`, пригодном для
сравнения и сортировки средствами SQLite.

Модуль `db/database.py` открывает соединение, включает проверку внешних ключей
и настраивает `sqlite3.Row`. Скрипт `db/import_json.py` переносит данные из JSON
в связанные таблицы внутри транзакции. Повторный запуск импорта не создаёт
дубликатов.

Файл `sql/queries.sql` содержит 12 проверенных запросов предметной области:

- получение списка и подробной карточки средства;
- поиск по названию, бренду и категории;
- фильтрацию по категории, остатку и сроку годности;
- соединение связанных таблиц с помощью `JOIN`;
- подсчёты `COUNT()` и `SUM()`;
- статистику по категориям и брендам с `GROUP BY`;
- фильтрацию групп с помощью `HAVING`.

Пользовательские значения передаются параметрами `?`, без подстановки в текст
SQL. Функции из `db/queries.py` выполняют запросы и используются
Django-представлениями.

## 11. Основные модули

### `models/products.py`

Содержит класс `Product` и операции над коллекцией средств: поиск, сортировку, изменение количества, удаление и расчёт статистики.

### `storage.py`

Отвечает за предыдущую реализацию загрузки и сохранения данных в формате JSON.

### `db/database.py`

Создаёт и настраивает соединение с отдельной SQLite-базой проекта.

### `db/import_json.py`

Переносит исходные данные из JSON в таблицы `brands`, `categories` и
`products`.

### `db/queries.py`

Содержит функции параметризованного выполнения запросов списка, поиска,
фильтрации и статистики.

### `homepage/views.py`

Содержит представление главной страницы и общий обработчик ошибки 404.

### `products/views.py`

Получает данные из SQLite и содержит представления списка, подробной страницы,
поиска, фильтрации, списка внимания и статистики.

### `main.py`

Содержит сохранённую консольную версию приложения.

### `utils.py`

Содержит вспомогательные функции безопасного консольного ввода.

## 12. Установка и запуск

Создать и активировать виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate
```

В Windows команда активации имеет вид:

```text
.venv\Scripts\activate
```

Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

Создать структуру отдельной базы и импортировать исходные данные:

```bash
python -m db.import_json
```

Команду импорта можно запускать повторно: существующие данные предметных таблиц
будут заменены актуальными данными из `data/products.json`.

Перед первым запуском применить встроенные миграции Django:

```bash
python manage.py migrate
```

Проверить конфигурацию:

```bash
python manage.py check
```

Запустить веб-сервер:

```bash
python manage.py runserver
```

После запуска веб-интерфейс доступен по адресу:

```text
http://127.0.0.1:8000/
```

Консольная версия запускается отдельно:

```bash
python main.py
```
