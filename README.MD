# Cosmetic Inventory System — система учёта косметики

## Назначение

Cosmetic Inventory System — приложение для учёта косметических средств,
контроля их количества и сроков годности.

Приложение позволяет:

* просматривать список косметических средств в браузере;
* просматривать подробную информацию о конкретном средстве;
* контролировать количество косметики;
* отслеживать сроки годности;
* определять средства, требующие пополнения или замены;
* искать средства по названию, бренду или категории;
* добавлять новые средства;
* изменять количество и удалять средства;
* сортировать средства по сроку годности;
* просматривать сводную статистику;
* хранить данные между запусками приложения.

## Используемые технологии

* Python 3 — язык программирования;
* Django 5.2 — веб-фреймворк;
* HTML — разметка веб-страниц;
* CSS и Bootstrap 5.3 — оформление страниц;
* JSON — хранение данных предметной области;
* pytest — автоматизированные тесты;
* flake8 — проверка качества кода.

## Целевая аудитория

* Частные пользователи с большим количеством косметических средств;
* Визажисты и бьюти-мастера;
* Сотрудники салонов красоты и магазинов косметики.

## Предметная область

Учёт косметических средств: хранение информации о продуктах, сроках годности,
категориях, брендах, количестве и статусе использования.


## Основные сущности

### Product — косметическое средство

Объект `Product` представляет косметическое средство, находящееся на учёте.

Основные атрибуты:

* `id` — уникальный идентификатор средства;
* `name` — название средства;
* `brand` — бренд;
* `category` — категория;
* `quantity` — количество единиц;
* `expiry_date` — срок годности в виде объекта `date`.

Основные методы:

* `validate_quantity()` — проверка корректности количества;
* `get_expiry_status()` — определение состояния срока годности;
* `get_quantity_status()` — определение состояния запасов;
* `needs_restock()` — проверка необходимости пополнения или замены;
* `change_quantity()` — изменение количества средства;
* `__str__()` — строковое представление средства.

## Страницы веб-интерфейса

* `/` — главная страница: описание приложения и навигация (view-функция
  `index()`);
* `/products/` — список средств из `data/products.json` с количеством, сроком
  годности и статусом (view-функция `products()`);
* `/products/<int:product_id>/` — подробная карточка средства
  (view-функция `product_detail()`);
* `/nonexistent/` и другие неизвестные адреса — собственная страница ошибки 404
  при `DEBUG = False` (view-функция `page_not_found()`).

Если средство с указанным идентификатором не найдено, страница возвращает
сообщение «Средство не найдено» и код статуса 404.

## Основные операции

### Используется в веб-интерфейсе

* просмотр списка косметических средств;
* просмотр информации о конкретном средстве;
* отображение количества и срока годности;
* определение средств, требующих внимания;
* вывод состояния запасов и срока годности;
* обработка неизвестных идентификаторов и адресов с кодом 404.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии.
В веб-интерфейсе они появятся после добавления форм и обработки
POST-запросов:

* добавление нового средства;
* поиск по названию, бренду или категории;
* сортировка по сроку годности;
* изменение количества;
* удаление средства;
* формирование списка покупок;
* просмотр сводной статистики.

## Хранение данных

Данные предметной области хранятся в JSON-файле:

* `data/products.json`.

Для каждого средства сохраняются идентификатор, название, бренд, категория,
количество и срок годности в формате `ГГГГ-ММ-ДД`. При загрузке записи JSON
преобразуются в объекты `Product`, а при сохранении объекты преобразуются обратно
в данные JSON.

Встроенная база данных SQLite используется Django только для служебных таблиц.
Сущность `Product` в Django ORM на текущем этапе ещё не переносилась.

## Назначение модулей

### `main.py`

Консольная версия приложения, сохранённая с ПР3. Отвечает за запуск приложения,
отображение меню, получение данных от пользователя и организацию пользовательских
сценариев.

### `cosmetic_inventory/`

Пакет настроек Django-проекта:

* `settings.py` — настройки проекта, приложений, локализации и базы данных;
* `urls.py` — маршрутизация верхнего уровня и обработчик ошибки 404;
* `asgi.py`, `wsgi.py` — точки взаимодействия с сервером.

### `homepage/`

Django-приложение, отвечающее за главную страницу и общий вид сайта:

* `views.py` — функция `page()`, view-функция `index()` и обработчик
  `page_not_found()`;
* `urls.py` — маршрут главной страницы;
* `models.py` — место для будущих Django-моделей приложения.

Функция `page()` формирует единый HTML-каркас, подключает Bootstrap 5.3 и создаёт
навигацию, которую используют остальные страницы.

### `products/`

Django-приложение, отвечающее за веб-страницы косметических средств:

* `views.py` — view-функции `products()` и `product_detail()`;
* `urls.py` — маршруты списка и карточки средства;
* `models.py` — место для будущей Django-модели `Product`.

View-функции загружают объекты `Product` из JSON и формируют HTTP-ответы со
списком средств, подробной информацией и статусами запасов и сроков годности.

### `models/`

Классы предметной области и функции работы с ними, созданные в ПР3:

* `products.py` — класс `Product`, поиск, сортировка, изменение количества,
  удаление и расчёт статистики;
* `__init__.py` — экспорт класса `Product`.

### `storage.py`

Отвечает за загрузку и сохранение данных. Выполняет преобразования:

* JSON → объекты `Product`;
* объекты `Product` → JSON.

### `utils.py`

Содержит вспомогательные функции консольного ввода:

* `input_int()` — безопасный ввод целого числа;
* `input_date()` — безопасный ввод даты.

### `tests/`

Содержит автоматизированные тесты:

* `test_products.py` — объектная модель и операции с коллекцией;
* `test_storage.py` — загрузка и сохранение JSON;
* `test_web.py` — маршруты, веб-страницы, данные и обработка ошибок 404.

## Запуск приложения

Установить зависимости:

```text
python -m pip install -r requirements.txt
```

Перед первым запуском применить встроенные миграции Django:

```text
python manage.py migrate
```

Проверить конфигурацию проекта:

```text
python manage.py check
```

Запустить веб-версию:

```text
python manage.py runserver
```

После запуска открыть в браузере:

```text
http://127.0.0.1:8000/
```

Консольная версия приложения сохранена и запускается командой:

```text
python main.py
```

## Тестирование

Для запуска автоматизированных тестов выполнить:

```text
pytest -v
```

Тесты проверяют объектную модель, операции над коллекцией, JSON-хранилище,
основные URL, формирование HTML-страниц и обработку ошибок 404.
